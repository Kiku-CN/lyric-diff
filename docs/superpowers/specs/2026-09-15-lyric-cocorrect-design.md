# Lyric CoCorrect 设计文档

## 目标

构建一个本地运行的歌词校对工具，将剪映导出的 `.srt`、`.txt` 或直接粘贴的文本与网易云歌词并排对照。工具不自动覆盖现场识别结果，用户逐行选择现场版、参考版或手动编辑，并能导出新的字幕文件。

## 用户流程

1. 用户粘贴歌词或上传 `.srt` / `.txt`。
2. 工具解析为统一的字幕行模型；`.srt` 保留序号和起止时间，纯文本按行生成无时间轴条目。
3. 用户可选填歌单，每行支持“歌名 - 歌手”。有歌单时优先按歌单搜索；没有歌单或匹配失败时，以片段前几句歌词搜索网易云候选。
4. 用户确认候选歌曲后进入校对视图。整场字幕按歌曲片段展示，串场和无法匹配的内容保留为“现场独有”。
5. 校对视图采用 git diff 风格，但表格行严格以输入文件为基线：每个 SRT 时间条目或 TXT 非空换行固定占一行。网易云歌词通过字符相似度分配到这些基线行内，允许一条输入行对应多条参考换行，不允许合并输入基线行。
6. 导出为新的 `.srt` 或 `.txt`：网易云文本（用户切换为现场版的行除外）作为默认真值，SRT 的开始/结束时间和条目顺序作为真值。

## 架构

- `src/lib/subtitles.ts`：解析和导出 SRT/TXT，纯函数，负责格式容错。
- `src/lib/alignment.ts`：基于归一化文本的序列对齐，输出 equal/change/add/remove 行。
- `src/server/netease.ts`：网易云搜索和歌词适配器；浏览器通过 Vite dev server 代理访问，失败时返回可展示的错误。
- `src/App.tsx`：页面状态、输入流程、片段/候选/校对交互。
- `src/styles.css`：单一页面的响应式视觉系统，桌面优先、窄屏纵向堆叠。

## 数据模型

```ts
type SubtitleEntry = {
  id: string;
  index: number;
  startMs?: number;
  endMs?: number;
  text: string;
};

type AlignmentRow = {
  id: string;
  kind: 'equal' | 'change' | 'add' | 'remove';
  localIds: string[];
  referenceText: string;
  chosenText: string;
};
```

## 失败与边界

- 空文件、无法识别的 SRT 时间轴和不支持的扩展名都显示行内错误。
- 网易云请求失败不阻塞本地 diff；视图显示“未获取参考歌词”，用户仍可导出现场版。
- 歌词行为空时不参与对齐，但原始字幕条目仍保留。
- 重复副歌不会被去重；对齐只按顺序匹配，现场独有行可以保留。
- 参考歌词多出的行没有时间轴，用户选择后也只作为可编辑草稿，不会伪造时间。

## 视觉与交互

- 内容优先的工作台：纸张背景 `#f6f4ef`，墨色 `#1d2421`，琥珀色用于差异和主要行动，蓝绿色用于成功状态。
- 顶部显示工具名、当前文件名和处理状态；输入区与校对区为全宽工作区，不使用层层嵌套卡片。
- 所有主要操作按钮包含文本和清晰的 hover/focus 状态；键盘可访问，颜色不是唯一状态提示。
- 桌面端左右两栏，宽度不足时自动改为上下两栏；歌词文本使用等宽字体提高逐行扫描效率。

## 验证

- Vitest 覆盖 SRT/TXT 解析、导出往返、对齐中的重复/插入/删除。
- `npm run check` 执行 TypeScript 检查和 Vitest。
- `npm run dev` 启动本地工具，手动验证文件导入、网易云错误态、diff 选择和导出下载。
